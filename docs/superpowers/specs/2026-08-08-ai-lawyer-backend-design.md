# AI-юрист: бэкенд для генерации трудового договора через Gemini

## Контекст

AgroRadar — фронтенд на Vite + React, без бэкенда. На странице `/contracts/create`
(`src/pages/ContractCreatePage.tsx`) уже есть трёхшаговый wizard "AI-юрист": пользователь
вводит имя работника, зарплату и обязанности, а на шаге 4 показывается статичный,
захардкоженный в JSX текст договора — реальной генерации нет.

Цель этого этапа — подключить настоящую генерацию содержательных пунктов договора через
Gemini API, вызываемую с бэкенда (ключ не должен попадать в клиентский бандл).

## Архитектура

```
Browser (ContractCreatePage) --POST--> /api/generate-contract (Vercel Function, Node)
                                              |
                                              v
                                   Gemini generateContent REST API
                                   (GEMINI_API_KEY читается из env на сервере)
```

- Бэкенд живёт в `/api` в корне репозитория — Vercel автоматически поднимает файлы
  оттуда как serverless-функции рядом со статическим Vite-билдом. Отдельного сервера/
  хостинга не требуется.
- `GEMINI_API_KEY` хранится в `.env` (уже создан и в `.gitignore`) и в Vercel env vars
  для деплоя — без `VITE_`-префикса, чтобы не попасть в клиентский бандл.
- Модель задаётся через `GEMINI_MODEL` (env, с дефолтом в коде), чтобы её можно было
  сменить без правки кода.

## Контракт эндпоинта

`POST /api/generate-contract`

Запрос:
```json
{
  "workerName": "Ерлан Смағұлов",
  "position": "Старший пастух КРС",
  "salary": "250 000",
  "duties": "Следить за 40 головами КРС...",
  "farmName": "Агро-Шаруашылық \"Өтеген батыр\"",
  "farmOwnerName": "Ерлан Смағұлов",
  "startDate": "2026-08-15",
  "endDate": "2026-11-15"
}
```

Ответ (200):
```json
{ "contractText": "1. ПРЕДМЕТ ДОГОВОРА: ...\n\n2. ОБЯЗАННОСТИ РАБОТНИКА: ...\n\n..." }
```

Gemini генерирует **только содержательные пункты** договора (предмет, обязанности,
права и обязанности сторон, срок, ответственность) обычным текстом с нумерованными
разделами. Шапку (номер договора, место/дата заключения, стороны) и блок подписей
фронтенд продолжает рендерить статично, как сейчас — так вывод остаётся визуально
предсказуемым независимо от форматирования модели.

Ошибки:
- `400` — не хватает обязательных полей запроса.
- `500` — не настроен `GEMINI_API_KEY` на сервере (лог на сервере, общее сообщение клиенту).
- `502` — Gemini API вернул ошибку или не ответил за 20 секунд (таймаут через AbortController).

## Фронтенд

В `ContractCreatePage.tsx` обработчик шага 3 → 4:
1. Показывает промежуточное состояние "AI составляет договор…" (спиннер вместо
   мгновенного перехода).
2. Делает `fetch('/api/generate-contract', { method: 'POST', body: JSON.stringify({...}) })`.
3. При успехе — сохраняет `contractText` в state, переходит на шаг 4, рендерит текст
   вместо старых захардкоженных `<p>`-абзацев (перенос строк сохраняется через
   `whitespace-pre-line` или разбивку по `\n\n`).
4. При ошибке — показывает сообщение об ошибке с кнопкой "Повторить" вместо перехода
   на шаг 4. Никакого fallback на фейковый текст — если генерация не удалась, это
   должно быть видно, а не маскироваться.

`addContract(...)` в `AppContext` вызывается только при успешной генерации, как и сейчас.

## Хранение

Без базы данных на этом этапе. Сгенерированный текст живёт там же, где сейчас живут
договоры — в React-контексте (`AppContext`), в памяти браузера. Это уже согласованная
с пользователем осознанная граница объёма работ; БД можно добавить позже отдельным
этапом, если понадобится персистентность между сессиями.

## Локальная разработка

`vite dev` не поднимает `/api`-функции. Для локальной проверки нужен `vercel dev`
(Vercel CLI) — он поднимает и статику, и serverless-функции на одном порту. Это
отдельно отмечается в README/инструкции для разработчика.

## Известный риск

Ключ, который эксплуатируется — `<см. .env, ключ не публикуется здесь>` — совпадает
по формату со стандартными ключами Google AI Studio. Если вызовы всё равно будут падать
с 401/403, нужно перепроверить, что ключ активен и включён доступ к нужной модели в
[aistudio.google.com/apikey](https://aistudio.google.com/apikey).

## Вне рамок этого этапа

- Telegram-бот и Telegram Mini App — отдельные последующие этапы (см. декомпозицию,
  согласованную с пользователем).
- Чат-консультант общего назначения (не только про договор) — не в этом этапе.
- База данных / персистентность договоров — не в этом этапе.
